# Развёртывание «Известия ЧГПУ» на Beget

## Что понадобится

- домен или поддомен;
- доступ к панели Beget;
- MySQL/MariaDB;
- PHP 8.1+;
- SSL для домена.

## Установка

1. Создать сайт/домен в панели Beget.
2. Создать базу MySQL и пользователя.
3. Загрузить проект в корень сайта.
4. Импортировать `backend/schema.sql`.
5. Скопировать `backend/config.example.php` в `backend/config.php`.
6. Внести реквизиты базы и реальный `base_url`.
7. Создать `backend/storage/uploads` и разрешить PHP запись.
8. Открыть `/backend/health.php` — должен вернуться `{"ok":true,...}`.
9. Создать первого администратора через `/backend/api/create-editor.php`.
10. Сразу удалить `create-editor.php`.
11. Проверить вход через `/login.html`.
12. Отправить тестовую статью через `/submit.html`.
13. Убедиться, что она появилась у редактора.
14. Настроить ежедневный backup базы и uploads.

## Не хранить в GitHub

- `backend/config.php`;
- пароли Beget/MySQL;
- резервные копии;
- приватные файлы авторов.

## После запуска

- импортировать подтверждённые выпуски;
- восстановить оставшиеся старые PDF;
- подключить e-mail уведомления;
- настроить официальный домен и редиректы.


## Резервные копии

После запуска проверить ручной backup в `/system.html`.

Для автоматического ежедневного backup настроить cron в панели Beget:

```
15 3 * * * /usr/bin/php /PATH_TO_SITE/backend/maintenance/backup.php
```

Путь к PHP и корню сайта уточняется в панели Beget.

Backup включает:
- SQL-дамп базы;
- архив `uploads`;
- manifest с SHA-256;
- автоматическое удаление копий старше `retention_days` (по умолчанию 30 дней).

Важно: хранить резервные копии не только на том же сервере. После запуска желательно настроить вторую копию вне Beget.

## Контроль целостности

В разделе `Система` администратор может:
- проверить наличие всех файлов;
- сравнить размер;
- сверить SHA-256;
- увидеть отсутствующие или повреждённые файлы;
- экспортировать данные системы в JSON.

## Системные ошибки

Фатальные PHP-ошибки пишутся в:
- таблицу `system_errors`;
- `backend/storage/system.log`.

Папки `storage/backups`, `storage/uploads` и файл `system.log` не должны попадать в Git.


## Обязательные настройки безопасности

Перед рабочим запуском:

1. В `backend/config.php` заменить:
   - `security.app_secret` на случайную строку не короче 32 байт;
   - `app.base_url` на реальный HTTPS-домен.
2. Включить SSL и проверить, что сайт открывается только по HTTPS.
3. В PHP-настройках установить ограничения не слабее:
   - `upload_max_filesize = 25M`;
   - `post_max_size = 40M`;
   - `max_file_uploads = 5`;
   - `display_errors = Off`;
   - `log_errors = On`.
4. После создания первого администратора удалить `backend/api/create-editor.php`.
5. Проверить, что прямое открытие:
   - `/backend/config.php`;
   - `/backend/storage/`;
   - `/backend/maintenance/`
   возвращает запрет доступа.
6. Проверить форму подачи:
   - DOC/DOCX;
   - PDF;
   - файл с неверным расширением;
   - файл больше лимита.
7. Проверить блокировку входа после серии неверных паролей.

## Реализованные меры защиты

- CSRF-токены для изменяющих запросов;
- проверка same-origin;
- rate limiting входа, подачи статей и доработок;
- honeypot и минимальное время заполнения публичной формы;
- проверка сигнатур DOC/DOCX/PDF;
- общий лимит загрузки;
- случайные имена файлов;
- закрытое файловое хранилище;
- разграничение ролей admin/editor/reviewer;
- защита от stored XSS;
- безопасные session cookies;
- CSP, HSTS, X-Frame-Options, nosniff и Permissions-Policy;
- аудит входов и событий безопасности;
- журнал ошибок без показа внутренних деталей пользователю.
