## 5. Изображения

Публичный поиск не даёт надёжно перечислить все JPG/PNG/WebP, привязанные к разделу журнала.

Важно:
- изображения, графики и схемы внутри выпусков находятся непосредственно в PDF и будут сохранены вместе с PDF;
- отдельные изображения WordPress (обложки, логотипы, миниатюры) для 100% гарантии нужно брать из `wp-content/uploads` старого хостинга;
- если доступа к старому хостингу не будет, можно собрать только те изображения, которые реально используются/индексируются публичными страницами.

## 6. Ограничение текущей проверки

Из текущей среды прямой запрос к chspu.ru периодически получает HTTP 502, хотя поисковый индекс видит страницы и прямые PDF.

Поэтому для массового физического скачивания лучше использовать один из вариантов:
1. экспорт `wp-content/uploads` со старого хостинга;
2. доступ к старому WordPress/FTP;
3. запуск миграционного скрипта непосредственно с нового сервера Beget.

Вариант 1 предпочтителен: так не потеряются даже неиспользуемые/непроиндексированные файлы.

## 7. Статусы миграции

Для каждого объекта дальше фиксируем:
- `DISCOVERED` — найден;
- `URL_VERIFIED` — прямой URL подтверждён;
- `DOWNLOADED` — скачан;
- `CHECKSUM_OK` — файл проверен;
- `UPLOADED_TO_BEGET` — загружен на новый сервер;
- `IMPORTED` — связан с записью в новой базе;
- `QA_OK` — визуально/функционально проверен.

## 8. Следующий шаг

Получить доступ к Beget и определить тип тарифа (виртуальный хостинг или VPS). После этого подготовить миграционный скрипт:
- обход архива;
- загрузка PDF/документов;
- вычисление SHA-256;
- сохранение исходного URL;
- загрузка на Beget;
- импорт записи выпуска в новую базу;
- отчёт по пропущенным/битым файлам.
